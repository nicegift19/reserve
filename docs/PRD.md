| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 (2026-10-20) |
| 상태 | 초안 — 프로토타입 완료, 정식 구현 대기 |

## 1. 배경

육군 동원사단 보병대대는 평시 현역 약 30명이 '동원준비태세 완비' 임무를 수행한다. 현역 간부 충원이 어려워지면서 상비예비군(최대 연 180일 복무)으로 결원을 메우고 있으나, 다음 질문에 답하는 공개 분석이 없다.

1. 현역과 상비예비군의 임무수행 능력과 비용은 얼마나 다른가?
2. 현역 1명을 대체하려면 상비예비군이 몇 명 필요한가?
3. 30·60·90·180일형을 어떻게 섞어야 가장 효율적인가?

## 2. 목표 / 비목표

### 목표
- G1. 위 세 질문에 대한 답을 첫 화면에서 바로 보여준다.
- G2. 모든 수치에 **출처 링크(팩트체크)** 또는 **계산식**을 붙여, 독자가 근거를 직접 검증할 수 있게 한다.
- G3. 지휘관·참모가 자기 부대 값으로 바꿔 볼 수 있는 **최적 조합 계산기**를 제공한다.
- G4. 정적 사이트로 웹 배포한다(서버·DB 없음).

### 비목표
- 실제 부대 편제·인원·예산 등 비공개 자료 수록 (공개 자료만 사용)
- 로그인, 사용자 데이터 저장, 관리자 화면
- 다국어

## 5. 기능 요구사항

### F1. 각주 출처 (팩트체크) — 필수
- F1.1 본문 사실 문장 끝에 `[n]` 각주. 클릭 시 `#src-n`으로 이동, 대상 항목 하이라이트(`:target`).
- F1.2 출처 항목은 `data/sources.json`에서 렌더링: 제목, 발행처, 유형, 검증 수준, **이 사이트가 인용한 내용**, 원문 URL(새 탭), 확인일.
- F1.3 검증 수준 배지 3종: `공식·학술`(초록), `2차 출처`(주황), `가정`(회색).
- F1.4 각주 번호와 sources.json의 id가 어긋나면 빌드 실패(테스트로 검증, §9).
- F1.5 (권장) 각주 hover/focus 시 출처 제목 툴팁.

### F2. 계산 기준과 방식 — 필수
- F2.1 `docs/METHODOLOGY.md`의 8단계를 그대로 페이지에 표기, 단계별 예시 계산 포함.
- F2.2 모든 입력값 옆에 검증 수준 배지와 각주.
- F2.3 본문·표에서 `단계 n` 링크로 해당 단계(`#m-stepN`)에 연결.
- F2.4 예시 계산의 숫자는 하드코딩하지 말고 `src/model.ts` 결과로 렌더링(값을 바꾸면 문서도 맞게 바뀌도록). 최소한 테스트로 일치 검증.

### F3. 최적 조합 계산기 — 필수
- 입력: 대체할 현역 수(1–15), 전시 직책 숙달 목표(0–40), 현역 1명당 관리 한도(0.5–4), 현역 1인 총비용(5,000–12,000만), 유형별 보상비·P·C·고정비·확보 가능 인원.
- 출력: 최적 조합(유형별 인원), 상태 배지(관리 가능/초과, 절감률, 180일형 한도 도달), 유효 근무일 구성 막대, 총비용·현역 유지 비용·절감액·총 인원·유효 근무일·평일 평균 출근 인원, 설명 문장.
- 알고리즘: METHODOLOGY 단계 8 (완전 탐색). 입력 변경 후 100ms 이내 갱신.
- 기본값으로 되돌리기 버튼.
- (권장) 입력값을 URL 쿼리로 공유 — 웹 배포 시 가능(아티팩트에서는 불가했음).

### F4. 차트
- 비용 막대 차트: 현역 1명분 업무량을 채우는 비용, 오른쪽에 필요 인원. 인라인 SVG, 테마 토큰 색상.
- (권장) 민감도 차트: 180일형 효율 0.4–1.0에 따른 현역 대비 비율 선 그래프.

### F5. 공통
- 라이트/다크 테마 (`prefers-color-scheme`).
- 모바일 400px에서 가로 스크롤 없음(표·차트만 내부 스크롤).
- 인쇄용 CSS(`@media print`): 계산기 입력 패널 숨김, 각주 URL 펼쳐 출력.
- 메타: OG 태그(제목, 설명, 이미지), favicon.

## 7. 기술 스택 (권장, 변경 가능)

- **Vite + TypeScript (바닐라)** — 프로토타입이 의존성 없는 바닐라 JS라 이식이 가장 쉽고 번들이 작음.
- 테스트: Vitest
- 배포: GitHub Pages / Vercel / Netlify 중 택1 (`docs/DEPLOYMENT.md`)
- 대안: 콘텐츠 페이지를 더 늘릴 계획이면 Astro.

## 8. 콘텐츠·데이터 원칙

1. 사실 문장 = 각주 필수. 각주 없는 사실 문장은 PR에서 반려.
2. 추정값은 반드시 `가정` 배지 + METHODOLOGY 링크.
3. 2차 출처는 공식 자료 확보 시 교체하고 `docs/SOURCES.md`의 '공식 대조 필요' 목록에서 제거.
4. 결론 문장의 숫자(예: "180일형 1.5명", "55~62%")는 모델 결과와 테스트로 일치 검증.

- [ ] 프로토타입의 모든 섹션·문구·수치가 동일하게 재현된다.

- [ ] 모든 외부 링크가 새 탭으로 열리고 `rel="noopener"`가 있다.

- [ ] Lighthouse 기준 충족.
